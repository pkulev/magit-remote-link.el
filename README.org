* *magit-remote-link.el* --- Actions with remote git hub links.

This package provides functions for copying and opening URLs to specific lines in a Git repository
on various hosting services.

* Installation
This package requires =magit= and relies heavily on magit's ability to extract remote
repository information from local Git repositories.

** use-package
#+begin_src elisp
  (use-package magit-remote-link
    :ensure nil
    :quelpa
    (magit-remote-link :repo "pkulev/magit-remote-link.el"
                       :fetcher github :upgrade t)
    :commands (magit-remote-link-copy-at-point magit-remote-link-browse-at-point)
    :bind (("C-c m w" . magit-remote-link-copy-at-point)
           ("C-c m W" . magit-remote-link-browse-at-point)))
#+end_src

* Usage
** Commands
Once installed, you can use the following interactive commands (=M-x=):

- =magit-remote-link-copy-at-point=: Copy the URL of the remote repository and the line at the point
  or in the active region to the clipboard.
- =magit-remote-link-browse-at-point=: Open the URL of the remote repository and the line at the
  point or in the active region in a browser.

Both commands prompt for the remote to link to.

To use these functions, navigate to a file in a Git repository in magit and place the cursor on a
line or select a region to specify the line number or range. Then use the key binding you configured
or run the function directly to copy or open the URL. The URL will be copied or opened with the line
number specified in the URL.

** Hosting providers
The web layout of a repository can't be derived from its clone URL in general (for example, GNU
Savannah clones from =git.savannah.nongnu.org/git/= but serves cgit from
=cgit.git.savannah.nongnu.org/cgit/=), so remotes are matched against rules:

- =magit-remote-link-hosts= maps a regexp on the remote's =HOST/PATH= to a provider and, optionally,
  a template for the web URL of the repository. Templates may use =%s= (scheme), =%h= (host), =%p=
  (path) and =\1= to =\9= (groups of the regexp). GitHub, GitLab, Bitbucket, Codeberg, SourceHut,
  NotABug and GNU Savannah (cgit) are built in; any other host is assumed to use the GitHub layout.
- =magit-remote-link-git-hosting-providers= defines the URL layout of each provider: GitHub, GitLab,
  Bitbucket, Gitea, Codeberg, SourceHut, NotABug and cgit. cgit has no line ranges, so a region links
  to its first line.

For example, to link a self-hosted cgit:

#+begin_src elisp
  (add-to-list 'magit-remote-link-hosts
               '("\\`git\\.example\\.com/\\(.*\\)\\'" cgit "https://web.example.com/cgit/\\1"))
#+end_src

A single remote can also be configured without touching Emacs settings, using git config:

#+begin_src sh
  git config remote.savannah.magit-remote-link-provider cgit
  git config remote.savannah.magit-remote-link-url https://cgit.git.savannah.nongnu.org/cgit/org-mode.git
#+end_src

Gitea has no built-in host rule, since its servers are self-hosted; select it with a
=magit-remote-link-hosts= entry (=("\\`git\\.example\\.com/" gitea)=) or the =magit-remote-link-provider= git config key.

Remote URLs may be =https://=, =ssh://=, =git+ssh://= or scp-style (=user@host:path=).

** Bindings
I have [[https://github.com/pkulev/.emacs.d#git-things][my magit stuff]] binded on the =C-C m= prefix, and for these commands my mnemonics are: Copy a
URL pointing to a line or a region in a file to the clipboard is more like =kill-ring-save= (=M-w=)
function, so =C-c m w= makes sense for me.  Opening the same URL in Web browser is =C-c m W= because
of W in the "Web", huh. Obviously =m= stands for =magit=.
